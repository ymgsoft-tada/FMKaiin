# コントロール・フォーム仕様

新しいデザインの画面(白基調・半透明パネル)で使う共通部品と、それを使って作ったフォームの仕様をまとめる。

- 1 章: 共通の決まり
- 2 章: 共通部品(コントロール / そのほかの補助のクラス / アイコン一覧)
- 3 章: FormMain2(新トップメニュー)
- 4 章: 表示倍率(DPI)と画面の大きさ

---

## 1. 共通の決まり

| 項目 | 決まり |
| --- | --- |
| 汎用コントロールの置き場所 | 共通ライブラリー comset の `UI/` フォルダー(`_Library/_All/comset/comset/UI/`。名前空間 `ComponentSUI`)。2026-11-26 に、FMKaiin の `Controls/`・`Controls/Common/`・`FormHelpers/` から移した(移したものの一覧と経過は、[Sコントロール仕様.md](../control/Sコントロール仕様.md) の 1.6)。ここに置くものは、このアプリに固有のものと、Gc 系に依存させない。このアプリに固有の部品(`IconLogo`・`OrganizationLogoShape`)と、使っていない `GradientForm`・`StepHeaderLabel` は、`FMKaiin/UI/`(名前空間 `App.Controls`)に残してある |
| フォーム汎用ヘルパの置き場所 | comset の `UI/`(`FontFallback`・`TitleBarColor`・`FunctionKeyBinder`。名前空間 `ComponentSUI`)。`FMKaiin/FormHelpers/` フォルダーは、2026-11-26 に無くした(2.2) |
| 新規作成時 | 特定の画面に依存しない部品は、comset の `UI/` に入れる(このアプリに固有のものは `FMKaiin/UI/`)。画面固有の処理はフォーム側に書く |
| 寸法の指定 | 自前描画コントロールの寸法プロパティは 96 DPI 基準のピクセル。描画時に `LayoutScale` で拡大する |
| フォームの拡大方式 | `AutoScaleMode.Dpi`。Designer の座標は 115 DPI(表示倍率 120%)基準 |
| フォント | BIZ UDPゴシック。PC に無い場合は `FontFallback` で Meiryo UI に差し替える |
| 文字コード・改行 | 新規ファイル(`.cs` / `.resx` / `.ps1`)は BOM 付き UTF-8・CRLF。既存ファイルは元の文字コードと改行を変えない(`FormFrame.cs` のように LF のファイルがある) |

#### 2.1.1 SideMenuButton

画面の左側に縦に並べる、区分選択用のボタン。`IconButtonBase` を継承し、アイコンと文字列を横並びで表示する。

| プロパティ | 既定値 | 内容 |
| --- | --- | --- |
| `Selected` | false | true のとき選択中の見た目(角丸の塗り + 選択時の文字色)で描く |
| `SelectedFillColor` | 38, 86, 134 | 選択中の塗り色 |
| `SelectedForeColor` | White | 選択中の文字とアイコンの色 |
| `HoverColor` | 230, 240, 248 | 選択していないときの、マウスオーバー時の背景色 |
| `CornerRadius` | 6 | 背景の角の半径 |
| `IconSize` | 22 | アイコンの一辺 |
| `IconLeft` | 14 | 左端からアイコンまでの間隔 |
| `TextGap` | 12 | アイコンと文字列の間隔 |

- 選択していないときは背景を持たない。マウスオーバー時と押下時だけ背景を付ける。
- 「複数のうち 1 つだけ選択」の制御は持たない。どのボタンを選択状態にするかは、置いた画面の側で決める。

## 3. FormMain2(新トップメニュー)

### 3.1 概要

- ログイン後に表示するトップメニュー。`GlassBackdropForm` を継承し、見た目の作りは FormNewMain を踏襲している。
- 左メニューで業務区分(会員登録 / 引き落とし業務 / マスター設定)を選ぶと、右側のボタン一覧がその区分のものに入れ替わる。
- 右側のボタンを押すと、対応する既存画面をモーダル(`ShowDialog`)で開く。
- 既存の FormMain / Form1 / FormReportMenu1 / FormReportMenu2 / FormExcelMenu に分かれていたメニューを、この 1 画面にまとめている。既存のメニュー画面は変更も削除もしていない。
- `Program.cs` は、ログイン後に FormMain2 を表示する。

### 3.3 左メニュー

| 表示名 | コントロール名 | アイコン | 表示するページ |
| --- | --- | --- | --- |
| 会員登録 | `navKaiin` | User | `pnlPageKaiin`(3.4) |

- 選択中の項目は、角丸の濃紺の塗り + 白い文字・アイコンで表示する。「>>」は表示しない。
- 選択していない項目は背景なし。マウスを乗せると淡い色の背景が付く。
- 常にどれか 1 つが選択されている。起動時は「会員登録」。
- クリック、またはフォーカスがある状態で Enter / Space で選択する。選択中の項目をもう一度選んでも何も変わらない。
- 選択すると、右側の見出しの文字(左メニューの表示名と同じ)と、表示するページが入れ替わる。フォーカスは左メニューに残る。

| --- | --- | --- | --- | --- |

## 4. 表示倍率(DPI)と画面の大きさ

開発 PC で「文字だけが大きく表示され、画面の大きさは変わらない」状態になっていた原因と、その対処。入力欄の文字が欠ける、ボタンの文字が収まらない、といった症状はこれによる。

### 4.1 原因

次の 2 つが重なって起きる。

| # | 要因 | 内容 |
| --- | --- | --- |
| 1 | PC の表示設定 | 開発 PC はカスタム スケーリング 120%(レジストリ `LogPixels=115`、`Win8DpiScaling=1`)。この PC では、DPI の指定がないプログラムも、実際の DPI(115)のまま動く。Windows による画面全体の拡大(ぼかして引き伸ばす表示)が行われない |
| 2 | `FormFrame` の設定 | `FormFrame.Designer.cs` が `AutoScaleMode = None` を設定している。派生フォームは `AutoScaleDimensions = (8, 20)` と `AutoScaleMode = Font` を指定しているが、None から Font に切り替わる時点で設計時の基準(8, 20)が捨てられるため、自動拡大が働かない |

1 により、ポイントで指定した文字は 1.2 倍の大きさで描かれる(メイリオ 9.75pt の行の高さが 20px から 24px になる)。2 により、フォームとコントロールの位置・大きさはデザイン時のピクセル値のまま変わらない。結果として、文字だけが大きくなる。

### 4.2 確認した内容

| 確認 | 結果 |
| --- | --- |
| 実行中の FMKaiin の DPI 対応状態 | 高 DPI 対応として動いている。画面の DPI は 115 |
| FMKaiin と同じ条件(マニフェストに DPI の指定なし)の検証プログラム | 起動直後から高 DPI 対応・DPI 115。アプリの処理や参照ライブラリが切り替えているのではない |
| マニフェストで DPI 非対応を明示した検証プログラム | 同じく高 DPI 対応・DPI 115 になる。この PC ではマニフェストで非対応にしても変わらない |
| 基底フォームを `AutoScaleMode = None` にした検証フォーム | 派生側で (8, 20) と Font を指定しても、大きさは 500 × 300 のまま。基底が既定値のフォームは 625 × 360 に拡大される |
| FormKaiin・FormMasterBasic を生成して調べた状態 | `AutoScaleDimensions` が (10, 24) に置き換わっており、フォームもコントロールもデザイン時の大きさのまま |

要因 1 が「カスタム スケーリングの設定によるもの」という点は、設定を変えての確認をしていない(レジストリの値と、検証プログラムの結果からの推定)。

### 4.3 影響する範囲

- 表示倍率 100% の PC では起きない(文字も画面も等倍)。
- 表示倍率を Windows の標準の選択肢(125%・150% など)で設定している PC では、DPI 非対応のプログラムは Windows が画面全体を拡大して表示するので、文字と画面の比率は崩れない見込み(この環境での確認はしていない)。
- `AutoScaleMode = Dpi` で作った画面(FormMain2・FormNewMain)は `FormFrame` を継承していないので、要因 2 の影響を受けない。

### 4.4 対処

`FormFrame` が、ロードの最初に 1 回だけ、画面の DPI に合わせてフォームとコントロールを拡大する(`FormFrame.cs` の `OnLoad` → `scaleForDeviceDpi`)。

| 項目 | 内容 |
| --- | --- |
| 拡大率 | 画面の DPI ÷ 96。この開発 PC では約 1.2 倍。縦横とも同じ倍率 |
| 96 DPI の PC | 何もしない(これまでと同じ表示) |
| タイミング | `OnLoad` の最初。画面を親の中央へ寄せる処理より前なので、拡大後の大きさで位置が決まる |
| 対象 | `FormFrame` を継承し、Designer で `AutoScaleMode = Font` を指定しているフォーム(現在は全フォーム) |
| DPI の取得 | `Graphics` から取得する。`DeviceDpi` プロパティは、このアプリでは実際の DPI にかかわらず 96 を返すので使えない |

仕組み: Windows フォームは「いまの文字の大きさ ÷ 基準(`AutoScaleDimensions`)」を拡大率にする。基準を 96 DPI のときの文字の大きさに設定し直してから `PerformAutoScale()` を呼ぶと、DPI の比率で 1 回だけ拡大される。レイアウトを止めた状態(`SuspendLayout`)で行う。止めずに基準を設定すると、その場で何も拡大しない自動拡大が走り、基準が元に戻る。

### 4.5 FormFrame.Designer.cs の AutoScaleMode = None を消してはいけない理由

None を消すと、派生フォームの自動拡大が `InitializeComponent` の中で働くようになるが、**Label の大きさだけが 2 回拡大される**(位置は 1 回)。ラベルが入力欄に重なり、Designer の表示とも食い違う。

起きる順番:

1. `FormFrame` が先にフォントを設定している。
2. 派生フォームの `InitializeComponent` で Label がフォームに追加されると、Label のフォントが変わる。
3. この時点でフォームは「拡大が必要」な状態なので、追加された Label がその場で拡大される(1 回目。位置と大きさ)。
4. Label は、フォントが変わったときに自分の大きさを設定し直す。この設定で「大きさは未拡大」という印が付き直す。
5. `InitializeComponent` の最後に、フォーム全体の拡大が行われ、印の付いた Label の大きさがもう一度拡大される(2 回目)。

`YcLabelEx` に限らず、標準の `Label`(`AutoSize = False`)でも起きる。テキスト ボックスなどは 4 の動作をしないので 1 回で済む。

そのため、`InitializeComponent` の間は None で自動拡大を止めておき、すべてのコントロールを追加し終えた後(4.4)で拡大している。

### 4.6 確認した内容と、残っている確認

| 確認 | 結果 |
| --- | --- |
| `FormFrame` を継承する 50 フォームを生成して拡大を実行 | フォーム直下の Label(自動サイズでないもの)が、位置・大きさとも 1 回分だけ拡大される。2 回呼んでも変わらない |
| `FormFrame` を継承した検証フォームを実際に表示 | コンストラクタでは拡大されず、`OnLoad` で 1 回だけ拡大される。`FormFrame_Shown` の `PerformAutoScale()` では変化しない |
| None を消した状態での再現 | Label が 2 回拡大されることを、拡大の呼び出し元を記録して確認(4.5 の順番) |

残っている確認:

- 各画面を実際に開いての見た目。グリッドの列幅など、コントロールの中の寸法は Windows フォームの拡大の対象外なので、文字に対して狭いままになる。
- `ShowDialog` で開いたときに、親の中央に表示されること。
- FormReportPreview は最大化して表示する画面なので、上の機械的な確認の対象から外した。

新しく作った部品(`FunctionKeyBar` など)は、拡大される場合・されない場合のどちらでも文字が収まるように作ってある。
